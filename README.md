# 3DP-MANAGER

Веб-приложение для управления подключениями и подписками через API [3x-ui](https://github.com/MHSanaei/3x-ui). Объединяет инбаунды нескольких нод в одну подписку с постоянным URL и обновляет их вручную или по расписанию.

## Возможности

- Несколько нод 3x-ui с авторизацией по токену или логину и паролю.
- Отдельный выбор ноды, relay, порта, флага и названия для каждого инбаунда.
- Существующий клиент из раздела Clients в 3x-ui или автоматическое создание клиента.
- Внешние ссылки подключений и профили маршрутизации Happ и INCY.
- Примечание, ссылки на поддержку и сайт, статистика трафика и срок действия подписки.
- Список SNI с импортом, экспортом и автопоиском доменов. При создании ноды или relay его домен добавляется в список автоматически, IP-адреса пропускаются.
- Фоновая генерация и удаление с ограничением нагрузки, повторными попытками и Журналом операций.

## Требования

- Сервер с Ubuntu или Debian и root-доступом для установочного скрипта.
- Docker и Docker Compose; установщик установит их при отсутствии.
- Одна или несколько панелей 3x-ui с доступными API инбаундов и Clients. Поддержка протоколов и токенов зависит от версии панели.
- Для relay — SSH-доступ к промежуточному серверу.
- Для TLS-инбаундов — сертификат и приватный ключ на соответствующей ноде.

## Установка

На сервере выполните от root:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/denpiligrim/3dp-manager/main/install.sh)
```

Установщик развернёт PostgreSQL, backend и frontend в `/opt/3dp-manager`. Можно выбрать HTTP или HTTPS с Let's Encrypt, собственным либо самоподписанным сертификатом. Адрес интерфейса, порт, логин и пароль выводятся в конце установки. После входа смените пароль в разделе **Настройки**.

## Настройка

1. В разделе **Ноды** добавьте URL панели 3x-ui, данные авторизации, IP и флаг. IP и страна определяются автоматически, их можно исправить вручную. Основная нода используется по умолчанию.
2. При необходимости добавьте промежуточный сервер в **Relay серверы**, выберите для него ноду и установите перенаправление через интерфейс. Хост relay можно указать доменом или IP.
3. В **Доменах** настройте список SNI для подключений с Reality.
4. В **Подписках** заполните основные данные, добавьте инбаунды и, при необходимости, профили маршрутизации. Всего доступно до 20 элементов на подписку.
5. Сохраните подписку и запустите генерацию. Скопируйте её URL в клиентское приложение. Адрес подписки имеет вид `/bus/<UUID>` и сохраняется при ротации.

Поле **ID клиента** принимает ID, email или имя существующего клиента 3x-ui. Он должен быть доступен на каждой выбранной ноде. Если поле пустое, приложение создаёт клиента автоматически. Его идентификатор отображается под именем подписки.

Для автоматической генерации включите авторотацию у нужных подписок и задайте общий интервал от 10 минут. Ручное обновление доступно для одной подписки или всех активных подписок с включённой авторотацией.

## Типы подключений

| Тип | Транспорт и безопасность |
| --- | --- |
| `vless-tcp-reality` | VLESS TCP + Reality |
| `vless-xhttp-reality` | VLESS XHTTP + Reality |
| `vless-xhttp-get` | VLESS XHTTP, `packet-up`, uplink GET, без TLS |
| `vless-grpc-reality` | VLESS gRPC + Reality |
| `vless-ws` | VLESS WebSocket + TLS, путь `/ws` |
| `vmess-tcp` | VMess TCP |
| `shadowsocks-tcp` | Shadowsocks TCP |
| `trojan-tcp-reality` | Trojan TCP + Reality |
| `hysteria2-udp` | Hysteria2 UDP + TLS, Salamander |
| `custom` | Готовая внешняя ссылка |

Порт можно задать числом от `1` до `65535` или значением `random` для выбора из диапазона `10000–59999`. Порт должен быть доступен на ноде и, при использовании перенаправления, на relay.

Для Reality SNI выбирается из списка доменов: конкретное значение или `random`. Для WebSocket и Hysteria2 SNI берётся из домена или IP ноды. У WebSocket этот же адрес используется как Host. Relay меняет адрес подключения, а Host и SNI WebSocket остаются адресом ноды.

В Reality и VLESS WebSocket можно выбрать fingerprint. По умолчанию используется `firefox`.

### Сертификаты WebSocket и Hysteria2

Пути к сертификату и ключу определяются по адресу ноды:

| Адрес ноды | Сертификат | Приватный ключ |
| --- | --- | --- |
| Домен, например `second.denpiligrim.ru` | `/root/cert/second.denpiligrim.ru/fullchain.pem` | `/root/cert/second.denpiligrim.ru/privkey.pem` |
| IPv4 или IPv6 | `/root/cert/ip/fullchain.pem` | `/root/cert/ip/privkey.pem` |

Пути можно изменить в настройках инбаунда. Файлы должны существовать на ноде; приложение передаёт пути в 3x-ui.

## Фоновые задачи и Журнал

Генерация инбаундов, удаление подписок и нод, удаление relay и установка или удаление перенаправления выполняются в фоне. В интерфейсе отображается состояние задачи, повторный запуск защищён от дублирования.

Пакетная ротация обрабатывает подписки по одной и уступает очередь другим задачам между подписками. Временные ошибки создания и удаления инбаундов повторяются до трёх попыток с задержками и проверкой результата. Ошибка одной подписки не останавливает весь пакет.

В **Журнале** доступны прогресс, результаты и повторные попытки, фильтры по процессу и статусу, по 20 записей на странице. Журнал обновляется автоматически. Завершённые записи хранятся до 30 дней с ограничением в 50 000 событий.

Очередь сохраняется после перезапуска. Уже выполнявшаяся задача помечается как прерванная и не повторяется автоматически: перед новым запуском нужно проверить её результат на ноде.

Настройки пауз, поведение очереди и изменения API описаны в [документации фоновых операций](docs/background-operations.md).

## Обновление

Для установки, выполненной скриптом:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/denpiligrim/3dp-manager/main/update.sh)
```

Скрипт создаёт резервную копию БД в `/opt/3dp-manager/backups`, включает применение миграций и обновляет контейнеры. Сохраните `.env` и `docker-compose.yml`: они содержат параметры существующей установки.

При самостоятельном развёртывании обновляйте схему БД вместе с backend. Для фоновой очереди требуется миграция `1793300000000-add-operations`; подробнее — в [разделе об обновлении БД](docs/background-operations.md#обновление-бд).

## Удаление

Команда удаляет контейнеры проекта, том БД и каталог `/opt/3dp-manager`, включая находящиеся в нём резервные копии:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/denpiligrim/3dp-manager/main/delete.sh)
```
