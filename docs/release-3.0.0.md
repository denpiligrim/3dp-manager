# 3DP-MANAGER 3.0.0 — итоговый отчёт

Версия добавляет фоновые операции с контролем нагрузки, единых клиентов 3x-ui, новые параметры подключений и Журнал. Отчёт охватывает весь diff ветки `dp-new-release` относительно `main`, включая сохранённые исходные коммиты контрибьюторов, а не только финальный коммит.

## Подписки, клиенты и маршрутизация

- Создание подписки разделено на три шага: основные данные, инбаунды и маршрутизация. Лимит — 20 элементов на подписку.
- Можно выбрать существующего клиента из Clients в 3x-ui по ID/email/имени или создать его автоматически. Один клиент переиспользуется для инбаундов подписки на выбранных нодах.
- В списке подписок под именем показан идентификатор клиента.
- Добавлены примечание, ссылки на поддержку и сайт, выдача статистики трафика, лимитов и срока действия через метаданные подписки; при ошибке получения статистики используются сохранённые данные.
- Профили Happ и INCY выдаются в прямой и relay-подписке без создания инбаундов на панели. Поддержаны JSON/base64, команды add/onadd/off; у INCY также HTTP(S)-источники и ссылки autorouting. Некорректные профили отклоняются.
- URL подписки остаётся постоянным: `/bus/<UUID>`.

## Протоколы и настройки нод

- Добавлен `vless-xhttp-get`: XHTTP packet-up, uplink GET без TLS, с передачей дополнительных параметров транспорта в ссылку.
- `vless-ws` переведён на TLS с путём `/ws`. Host и SNI берутся из домена или IP ноды, в том числе при подключении через relay.
- Для Reality и VLESS WebSocket доступен выбор fingerprint; значение по умолчанию — `firefox`. Явно выбранные значения сохраняются.
- WebSocket и Hysteria2 используют сертификат и ключ из `/root/cert/<домен>/` либо `/root/cert/ip/` для IPv4/IPv6. Пути доступны для ручного изменения и передаются в конфигурацию панели.
- При добавлении ноды или relay домен автоматически сохраняется в список SNI. IP пропускаются; регистр нормализуется, дубликаты не создаются, статус существующей записи сохраняется. Создание ресурса и SNI выполняется в одной транзакции.
- После добавления relay можно сразу установить перенаправление через интерфейс.

## Надёжность и совместимость 3x-ui

- Необязательное `tgId` не отправляется при создании клиентов; чтение допускает старую строковую и новую числовую схемы.
- Для авторизации паролем поддержан CSRF до и после входа. Сохранены API-токены и работа со старыми панелями без CSRF endpoint.
- Сессии и HTTP-соединения переиспользуются; при изменении учётных данных сессия обновляется.
- Создание и удаление инбаундов имеют до трёх попыток при временных ошибках с увеличивающимися задержками.
- При потере ответа создание проверяется по уникальному tag. Если результат нельзя подтвердить, слепой повтор не отправляется. После потери ответа удаления проверяется наличие инбаунда.
- Исправлен адрес назначения Trojan-ссылок: адрес ноды/relay используется для соединения, маскирующий домен остаётся в SNI.
- Отказы панели влияют на результат генерации; скрипт `server/scripts/probe-xui.mjs` сохранён для отдельной диагностики совместимости.

## Очередь, ротация и удаление

- Генерация, удаление подписок и нод, удаление relay и установка/удаление перенаправления выполняются через сохраняемую в PostgreSQL очередь.
- API возвращает `202 Accepted` и `jobId`. Фронтенд отслеживает задачу до результата; ошибки удаления сохраняют структурированный код для предложения принудительного удаления.
- Повторная постановка той же незавершённой задачи возвращает существующий ID. Один обработчик владеет PostgreSQL advisory lock; проверка соединения блокировки останавливает дальнейшие изменения при его потере.
- Подписки выбираются страницами по 10 идентификаторов, связи загружаются для одной подписки за раз.
- После подписки сохраняется контрольная точка, пакет уступает очередь другим задачам. Ошибка отдельной подписки не останавливает остальные.
- Сначала создаётся новый набор, затем удаляется старый. Незавершённые замены скрыты от клиентской выдачи. Неудачная очистка сохраняется и повторяется до выделения новых ресурсов, предотвращая накопление инбаундов.
- Очистка затрагивает только управляемые записи; отсутствие чужого инбаунда в БД не является основанием для его удаления.
- Сохранены явные принудительные операции для недоступных нод и подписок. Принудительная ротация намеренно оставляет старые удалённые инбаунды на панели. Проверена очистка зависимостей при удалении последней ноды.
- Очередь переживает перезапуск. Выполнявшаяся задача помечается прерванной и не повторяется автоматически, пока результат на ноде не проверен.

## Интерфейс, Журнал и документация

- Обновлены светлая и тёмная темы и фон формы входа.
- В области уведомлений показан индикатор длительной операции. Защита от повторного запуска действует до окончания запроса и обновления данных; подтверждения и меню действий закрываются своевременно.
- Новый раздел «Журнал»: создание/изменение/удаление подписок, нод и relay, генерация инбаундов, прогресс, результаты и повторные попытки.
- Фильтры по процессу и статусу, обновление каждые 5 секунд, согласованная серверная и клиентская пагинация по 20 записей. При очистке записей страница возвращается в доступный диапазон.
- Таблица обрезается по скруглённым границам контейнера.
- Журнал не сохраняет учётные данные подключения, клиентские секреты и вывод SSH. Завершённые события хранятся до 30 дней и ограничены 50 000 записями.
- Русский README актуализирован; синхронизированы английская, китайская, персидская и туркменская версии. Картинка и бейджи сохранены.

## Обновление и совместимость API

- Применить миграции `1793200000000-add-subscription-client`, `1793200000001-add-subscription-metadata` и `1793300000000-add-operations`, если они ещё не применены.
- При отключённой синхронизации схемы использовать `DB_MIGRATIONS_RUN=true`; существующий скрипт обновления создаёт резервную копию БД и включает миграции.
- Прямые потребители API должны дождаться терминального статуса `/api/operations/:id`: ответ `202` означает постановку в очередь, а не завершение.
- `PANEL_MUTATION_INTERVAL_MS` — пауза изменений на панели, по умолчанию 300 мс; `ROTATION_SUBSCRIPTION_PAUSE_MS` — пауза между подписками, 500 мс.
- Подробности: [фоновые операции](background-operations.md).

### Известный долг клиентских тестов

Первый полный клиентский прогон: **281 тест прошёл, 74 упали**. Из них 8 устаревших ожиданий новой темы и текста уведомления исправлены; последующий прогон всех остальных 26 файлов завершился успешно: **278/278**.

Остаются два старых набора с ожиданиями удалённого интерфейса:
- `SettingsPage.spec.tsx`: 2 проходят, 36 падают.
- `TunnelsPage.spec.tsx`: 9 проходят, 30 падают.

Эти 66 падений уже описаны в историческом отчёте интеграции; SettingsPage и сами два тестовых файла не менялись относительно `main`. Они явно исключены из повторного зелёного прогона, а не объявлены исправленными. Обновление их сценариев до текущей структуры Settings/Nodes/Subscriptions/Relay остаётся отдельной работой.

### Пределы проверки

Нагрузочный прогон на рабочих нодах, проверка реальных панелей разных версий, импорт подписок на устройствах Happ/INCY и полная установка/обновление через Docker не выполнялись. Проверки PostgreSQL проводились в изолированном тестовом контейнере, запросы к панелям в автоматических тестах моделировались.
