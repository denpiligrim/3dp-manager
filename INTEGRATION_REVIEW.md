## Разрешение пересечений

- `tgId`: выбран вариант PavelArs с отсутствующим необязательным полем вместо
  пустой строки или нуля. Типы чтения допускают старое строковое значение и новое
  числовое. Тесты обоих авторов сохранены и согласованы с итоговым поведением.
- `test-fix`: логика перенесена из скомпилированного патча в TypeScript-сервис.
  Скрипт подмены файлов в работающем контейнере не нужен. Новые инбаунды создаются
  до очистки старых; при отказе создания старые подключения остаются доступны.
- Глобальная очистка чужих инбаундов не перенесена: отсутствие удалённого ID в
  нашей БД не означает, что его можно удалить. Очистка выполняется только по
  старым записям текущей подписки, с нодой каждой записи. Если удаление не удалось,
  локальная запись остаётся для повторной попытки и API возвращает неуспех.
- `force=true` явно пропускает удаление старых конфигов на панели, но убирает
  старые локальные записи только после успешного создания новых. Старые удалённые
  конфиги при таком выборе остаются на панели и могут требовать ручной очистки.
- При частичном отказе создания уже созданные новые инбаунды сохраняются вместе
  со старыми. Следующая ротация учитывает их как управляемые записи. Это позволяет
  сохранить доступность без удаления рабочих подключений.
- Отказы панели теперь влияют на результат API, а не только на журнал.
  Порт в БД берётся из реально отправленного конфига после возможной смены порта.
- Исправлено замыкание в диалоге ротации: режим force передаётся при подтверждении,
  поэтому переключатель после открытия диалога действительно влияет на запрос.
- CSRF-cookie запрашивается до входа, токен обновляется после смены сессии;
  старые панели и API-токены продолжают поддерживаться. Токен прежней сессии не
  используется при неуспешном обновлении. Одновременные логины основной панели
  используют один выполняющийся запрос авторизации.
- Из `fix-deletion` исключены настройки локального эксперимента: SQLite вместо
  PostgreSQL, замена bcrypt, стандартные admin/admin, отключение миграций,
  смена порта сервера и встроенная раздача фронтенда. Существующая конфигурация
  установки, зависимости, миграции и версия пакета сохранены.
- Поддержка Happ из текущей ветки сохранена. Профили не создают инбаундов в панели.

## Ручная проверка

1. Проверить вход и список нод на используемой версии 3x-ui; отдельно проверить
   авторизацию паролем и API-токеном. Для новой панели проверить CSRF.
2. Обновить подписку с random и фиксированными портами, включая Trojan и Happ;
   проверить выдаваемый адрес, SNI, порт и импорт подписки клиентом.
3. Имитировать отказ создания инбаунда: API сообщает неуспех, старые ссылки
   сохраняются. Имитировать отказ удаления: запись остаётся для повторной очистки.
4. Проверить обычную и принудительную ротацию одной и всех активных подписок.
   При force старые конфиги остаются на панели согласно выбранному режиму.
5. Для недоступной ноды проверить отказ обычного удаления и успешное принудительное.
   Проверить отмену диалога: переключатель сбрасывается.

`server/scripts/probe-xui.mjs` сохранён как отдельный диагностический инструмент.
Он создаёт реальные тестовые инбаунды; в ходе этой проверки на живой панели
не запускался. По умолчанию удаляет только созданные им инбаунды, с `--keep`
оставляет их. Приватные Reality-ключи в журнал не выводятся.

## Дополнение: маршрутизация INCY

Добавлен тип `incy-routing` с тем же полем `routingProfile`, что и у Happ.
Поддержаны JSON/base64, команды `incy://routing/add/...`, `onadd` и `off`.
HTTP(S)-URL превращается в `incy://autorouting/add/<URL>`; готовые ссылки
автообновления сохраняют назначение. URL скачивает приложение INCY, сервер
не выполняет сетевые запросы к источнику профиля. Профиль выдаётся и в прямой,
и в relay-подписке, без создания инбаунда на панели.

В форме подписки появились отдельные кнопки добавления Happ и INCY.
Прежние сохранённые профили Happ и их формат продолжают поддерживаться.
Описание API и примеры добавлены в `api.md`.

Серверная сборка и все 25 наборов / 338 тестов проходят. На клиенте 47 сценариев
страницы подписок прошли в общем прогоне; новый сценарий добавления INCY
проверен отдельно после исправления поиска кнопки и замены тяжёлой стартовой
формы на компактную форму редактирования. Проверены все 48 сценариев страницы
в этих прогонах. Коммит не создавался, родители подготовленного merge сохранены.
