# 3DP-MANAGER

یک برنامهٔ وب برای مدیریت اتصال‌ها و اشتراک‌ها از طریق API پنل [3x-ui](https://github.com/MHSanaei/3x-ui). این برنامه اتصال‌های ورودی چند نود را در یک اشتراک با URL ثابت ترکیب می‌کند و آن‌ها را به‌صورت دستی یا طبق زمان‌بندی به‌روزرسانی می‌کند.

## امکانات

- مدیریت چند نود 3x-ui با احراز هویت از طریق توکن یا نام کاربری و گذرواژه.
- انتخاب جداگانهٔ نود، سرور relay، پورت، پرچم و نام برای هر اتصال ورودی.
- استفاده از کلاینت موجود در بخش Clients پنل 3x-ui یا ساخت خودکار کلاینت.
- افزودن لینک اتصال خارجی و پروفایل‌های مسیریابی Happ و INCY.
- یادداشت اشتراک، لینک پشتیبانی و وب‌سایت، آمار ترافیک و اطلاعات انقضا.
- فهرست دامنه‌های SNI با امکان ورود، خروج و جست‌وجوی خودکار. هنگام ایجاد نود یا relay، دامنهٔ آن به‌صورت خودکار اضافه می‌شود؛ آدرس‌های IP اضافه نمی‌شوند.
- تولید و حذف در پس‌زمینه با محدودسازی بار، تلاش مجدد و ثبت رویدادهای عملیات.

## پیش‌نیازها

- سرور Ubuntu یا Debian و دسترسی root برای اجرای اسکریپت نصب.
- Docker و Docker Compose؛ در صورت نبودن، نصب‌کننده آن‌ها را نصب می‌کند.
- یک یا چند پنل 3x-ui با API فعال اتصال‌های ورودی و Clients. پشتیبانی از پروتکل‌ها و توکن‌ها به نسخهٔ پنل بستگی دارد.
- دسترسی SSH به سرور واسط برای راه‌اندازی relay.
- گواهی و کلید خصوصی روی نود مربوطه برای اتصال‌های ورودی TLS.

## نصب

روی سرور با دسترسی root اجرا کنید:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/denpiligrim/3dp-manager/main/install.sh)
```

نصب‌کننده PostgreSQL، بک‌اند و فرانت‌اند را در `/opt/3dp-manager` مستقر می‌کند. می‌توانید HTTP یا HTTPS با گواهی Let's Encrypt، گواهی شخصی یا گواهی خودامضا را انتخاب کنید. آدرس رابط، پورت، نام کاربری و گذرواژه در پایان نصب نمایش داده می‌شوند. پس از ورود، گذرواژه را در بخش **تنظیمات (Настройки)** تغییر دهید.

## پیکربندی

1. در بخش **نودها (Ноды)**، URL پنل 3x-ui، اطلاعات احراز هویت، IP و پرچم را وارد کنید. IP و کشور به‌صورت خودکار شناسایی می‌شوند و قابل اصلاح دستی هستند. نود اصلی به‌عنوان پیش‌فرض استفاده می‌شود.
2. در صورت نیاز، سرور واسط را در بخش **سرورهای Relay (Relay серверы)** اضافه کنید، نود مقصد را انتخاب کرده و انتقال ترافیک را از طریق رابط نصب کنید. میزبان relay می‌تواند دامنه یا IP باشد.
3. در بخش **دامنه‌ها (Домены)**، فهرست SNI برای اتصال‌های Reality را تنظیم کنید.
4. در بخش **اشتراک‌ها (Подписки)**، اطلاعات اصلی، اتصال‌های ورودی و در صورت نیاز پروفایل‌های مسیریابی را اضافه کنید. هر اشتراک در مجموع می‌تواند تا 20 مورد داشته باشد.
5. اشتراک را ذخیره کرده و تولید اتصال‌ها را شروع کنید. URL اشتراک را در برنامهٔ کلاینت کپی کنید. این آدرس به‌شکل `/bus/<UUID>` است و هنگام چرخش اتصال‌ها ثابت می‌ماند.

فیلد **شناسهٔ کلاینت**، ID، ایمیل یا نام کلاینت موجود در 3x-ui را می‌پذیرد. این کلاینت باید روی تمام نودهای انتخاب‌شده در دسترس باشد. اگر فیلد خالی باشد، برنامه کلاینت را به‌صورت خودکار می‌سازد. شناسهٔ آن زیر نام اشتراک نمایش داده می‌شود.

برای تولید زمان‌بندی‌شده، چرخش خودکار را برای اشتراک‌های موردنظر فعال کرده و فاصلهٔ زمانی مشترک را حداقل 10 دقیقه تنظیم کنید. به‌روزرسانی دستی برای یک اشتراک یا تمام اشتراک‌های فعال با چرخش خودکار روشن در دسترس است.

## انواع اتصال

| نوع | انتقال و امنیت |
| --- | --- |
| `vless-tcp-reality` | VLESS TCP + Reality |
| `vless-xhttp-reality` | VLESS XHTTP + Reality |
| `vless-xhttp-get` | VLESS XHTTP، حالت `packet-up`، ارسال بالادستی با GET، بدون TLS |
| `vless-grpc-reality` | VLESS gRPC + Reality |
| `vless-ws` | VLESS WebSocket + TLS، مسیر `/ws` |
| `vmess-tcp` | VMess TCP |
| `shadowsocks-tcp` | Shadowsocks TCP |
| `trojan-tcp-reality` | Trojan TCP + Reality |
| `hysteria2-udp` | Hysteria2 UDP + TLS، Salamander |
| `custom` | لینک اتصال خارجی آماده |

پورت می‌تواند عددی از `1` تا `65535` یا مقدار `random` برای انتخاب از بازهٔ `10000–59999` باشد. پورت باید روی نود و در صورت استفاده از انتقال ترافیک، روی relay نیز در دسترس باشد.

برای Reality، یک دامنهٔ مشخص یا مقدار `random` از فهرست دامنه‌های SNI انتخاب می‌شود. WebSocket و Hysteria2 از دامنه یا IP نود به‌عنوان SNI استفاده می‌کنند. WebSocket همین آدرس را برای Host نیز به کار می‌برد. Relay آدرس مقصد اتصال را تغییر می‌دهد، اما Host و SNI در WebSocket همچنان آدرس نود هستند.

در Reality و VLESS WebSocket می‌توانید fingerprint را انتخاب کنید. مقدار پیش‌فرض `firefox` است.

### گواهی‌های WebSocket و Hysteria2

مسیرهای پیش‌فرض گواهی و کلید بر اساس آدرس نود تعیین می‌شوند:

| آدرس نود | گواهی | کلید خصوصی |
| --- | --- | --- |
| دامنه، مانند `second.denpiligrim.ru` | `/root/cert/second.denpiligrim.ru/fullchain.pem` | `/root/cert/second.denpiligrim.ru/privkey.pem` |
| IPv4 یا IPv6 | `/root/cert/ip/fullchain.pem` | `/root/cert/ip/privkey.pem` |

می‌توانید مسیرها را در تنظیمات اتصال ورودی تغییر دهید. فایل‌ها باید روی نود موجود باشند؛ برنامه مسیر آن‌ها را به 3x-ui ارسال می‌کند.

## وظایف پس‌زمینه و گزارش عملیات

تولید اتصال‌های ورودی، حذف اشتراک‌ها و نودها، حذف relay و نصب یا حذف انتقال ترافیک در پس‌زمینه انجام می‌شوند. رابط وضعیت وظیفه را نمایش می‌دهد و از اجرای تکراری جلوگیری می‌کند.

چرخش گروهی، اشتراک‌ها را یکی‌یکی پردازش می‌کند و بین اشتراک‌ها به دیگر وظایف صف فرصت اجرا می‌دهد. خطاهای موقت ایجاد یا حذف اتصال ورودی، حداکثر تا سه تلاش با تأخیر و بررسی نتیجه پیگیری می‌شوند. خطای یک اشتراک باعث توقف کل گروه نمی‌شود.

بخش **گزارش عملیات (Журнал)**، پیشرفت، نتایج و تلاش‌های مجدد را با فیلتر فرایند و وضعیت و 20 رکورد در هر صفحه نشان می‌دهد. این بخش به‌صورت خودکار به‌روزرسانی می‌شود. رویدادهای تکمیل‌شده حداکثر 30 روز و تا سقف 50,000 رویداد نگهداری می‌شوند.

صف پس از راه‌اندازی مجدد برنامه حفظ می‌شود. وظیفه‌ای که در حال اجرا بوده، به‌عنوان قطع‌شده علامت‌گذاری می‌شود و خودکار دوباره اجرا نمی‌شود؛ پیش از اجرای مجدد، نتیجهٔ آن را روی نود بررسی کنید.

تنظیمات تأخیر، رفتار صف و تغییرات API در [مستندات عملیات پس‌زمینه](docs/background-operations.md) به زبان روسی آمده است.

## به‌روزرسانی

برای نصب‌هایی که با اسکریپت انجام شده‌اند:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/denpiligrim/3dp-manager/main/update.sh)
```

اسکریپت از پایگاه داده در `/opt/3dp-manager/backups` پشتیبان می‌گیرد، اجرای مهاجرت‌های پایگاه داده را فعال می‌کند و کانتینرها را به‌روزرسانی می‌کند. فایل‌های `.env` و `docker-compose.yml` را نگه دارید؛ این فایل‌ها شامل تنظیمات نصب فعلی هستند.

در استقرار دستی، ساختار پایگاه داده را همراه با بک‌اند به‌روزرسانی کنید. صف پس‌زمینه به مهاجرت `1793300000000-add-operations` نیاز دارد؛ جزئیات در [بخش به‌روزرسانی پایگاه داده](docs/background-operations.md#обновление-бд) به زبان روسی آمده است.

## حذف

این فرمان کانتینرهای پروژه، volume پایگاه داده و پوشهٔ `/opt/3dp-manager` را همراه با پشتیبان‌های داخل آن حذف می‌کند:

```bash
bash <(curl -fsSL https://raw.githubusercontent.com/denpiligrim/3dp-manager/main/delete.sh)
```
